# Differences from Ghidra

Gosleigh's baseline is the output of Ghidra 12's decompiler for the same input. This file lists
every place where Gosleigh behaves differently on purpose. Anything not listed here and not equal
to Ghidra is a bug.

## Always on

These differ from Ghidra with no option to turn them off.

| Area | Ghidra | Gosleigh | Why | Upstream |
|---|---|---|---|---|
| Order of call parameter trials | Sorted by pointer address (`ParamTrial::operator<`), so the result can change between runs | Sorted by position in the compiler spec | Same input, same output | [ghidra#9750](https://github.com/NationalSecurityAgency/ghidra/pull/9750) |
| Constant stored into a bitfield as `(v & clear) \| set` where neither mask covers the whole field | Ghidra 12.1 prints the masks | Prints `p->mode = 5` | Reads as the source wrote it | [ghidra#9836](https://github.com/NationalSecurityAgency/ghidra/pull/9836) |
| Default instruction limit for flow (`decomp.DefaultMaxInstructions`) | 100000 | 20000; set `decomp.Function.MaxInstructions` to change it | Bounds time and memory per function. As in Ghidra, a flow over the limit fails the function (`bridge.ErrTooManyInstructions`) instead of being cut short | - |

## Opt-in

Without these options the decompiler behaves as Ghidra does.

To get everything that is measured to keep every function Ghidra decompiles
correctly unchanged, a host does not pick options one by one: it makes
`analysis.NewEnhanced(prog)` once per program and calls `Apply(&fn)` on each
`decomp.Function`. An option joins that preset only after the measurement
(real-binary goldens, `tools/realexe/realexe.py measure-all`) shows no
function Ghidra gets right changing for the worse.

| Option | Ghidra | Gosleigh with the option | Use |
|---|---|---|---|
| `decomp.Function.FlowBounds` | A decompile always follows flow over the whole address space | Flow is limited to the given ranges (several for a split function); leaving them ends in Ghidra's own out-of-bounds handling ("Function flow out of bounds" + `halt_missing()`) | Functions whose whole-space flow runs into junk bytes |
| `decomp.Function.Extensions.NestedPieceTrials` | When an XMM register is written lane by lane (`cvtdq2ps`), as a scalar (`movss` from memory zeroes the upper lanes) and whole (`movaps`) in one function, heritage joins it in nested PIECEs; `AncestorRealistic` and `ancestorOpUse` then reject the value, so a float return prints as `void` and a float argument of a call without a prototype is dropped, each with the code computing it | Such a trial is followed into a low piece that holds it, and PIECE / same-register SUBPIECE steps do not use up `ancestorOpUse`'s 5 recursion levels. For call arguments the extension only fills a parameter slot Ghidra left empty: if Ghidra accepted another register of the same slot (RDX for XMM1), Ghidra's argument stays | x64 code that passes or returns floats in XMM registers |
| `decomp.Function.Extensions.NarrowFloatReturns` | A float returned in an 8-byte slot (x64 XMM0_Qa) keeps all 8 bytes alive when one path returns a float parameter register unchanged (`movaps xmm0, xmm1`): the function returns `ulonglong`, results print as `(ulonglong)(uint)(...)` and the parameter becomes an integer | The return is cut to its low 4 bytes when every path returns a 4-byte float result, a 4-byte value, a constant, a call result or a float parameter unchanged, and at least one path is a 4-byte float operation; a double (8-byte float operation) is never cut | x64 functions returning `float` |
| `decomp.Function.Extensions.NaNExactCompares` | The negation of a float order comparison is rewritten to the swapped comparison (`!(a < b)` to `b <= a`, `get_booleanflip` in RuleBoolNegate and the printer's negated tokens); the two differ when an operand is NaN, so `minss` prints with the NaN case taken the wrong way | The negation stays: `!(a < b)`. When the decompiler drops a NaN test (`comiss` sets the flags so that `ja` is not taken for NaN; Ghidra drops the test and prints the NaN case on the other branch), the comparison left is rewritten to the form with the same NaN value and no `NAN()` test: `comiss x, c; ja` prints `if (!(c < x))`. A value that cannot be NaN (an integer converted to float, a constant) is left as Ghidra prints it. To keep every NaN test, see `NaNIgnore` below | Code where NaN matters |
| `decomp.Function.Extensions.BitCastSyntax` | A CAST between a float and an integer (a bit reinterpretation such as `movd xmm0, edx`) and a numeric conversion (`INT2FLOAT`) both print as `(float)x` | The CAST prints as `bit_cast<float>(x)`; a conversion stays `(float)x` | Float tricks such as `bit_cast<float>(x >> 9 \| 0x3f800000) - 1.0` |
| `decomp.Function.Extensions.FloatLoads` | A narrow load through a pointer to a wider integer is widened to the element and truncated (RuleExpandLoad), so a float field read through a `longlong *` prints as `(int)p[0x3c8]` | A load whose value is used as a float (a float operation, or a float parameter slot of a call) stays a load: `*(undefined4 *)(p + 0x3c8)` | Float fields in objects typed as integer arrays |
| `decomp.Function.Extensions.CurrentSwitchLabels` | Case labels reverse the flow-time model's values through the current model's path. When the two chose different normalized variables (a byte switch `lea eax,[rsi-0x80]` computed twice: at flow time the guard misses the second copy, after CSE it matches), the labels are off by the normalization: `case 0x100:` for 0x80, with "may not be properly labeled" | When the flow-time values are outside the current range, the current range is used, but only if emulating it rebuilds exactly the recovered address table | Byte or offset switches (`tp - 0x80` jump tables) |
| `decomp.Function.Extensions.AllocaReturnStores` | After `sub rsp, rax` (alloca) the stack pointer is not a constant frame offset, so the return address store of every call stays: `*(undefined8 *)((longlong)&local_10 + -param_1) = 0x14000100c;` | In a function that moves its stack pointer by a register, the return address store of each call is dropped (not for a call to its own fall-through, `call $+5; pop`). Other functions are not changed | Functions with dynamic stack allocation |
| `decomp.Function.Extensions.NoFloatAddresses` | Float ranks above integer in type propagation, so a value that is only an integer register (`this` in RCX) takes a double type across a COPY into a stack slot that is later reused as a double temporary: `void f(double param_1)` with every field access printed as `bit_cast<longlong>(param_1) + 0xd8` | A float type does not propagate into a value used as a LOAD/STORE address or as the base of the addition (or copy, 3 deep) computing one | Homed parameters whose slot is reused for a float |
| `decomp.Function.Extensions.SelfCancelNoUse` | A parameter trial is dropped when its value reaches another call with a locked prototype (`Funcdata::onlyOpUse`, `checkCallDoubleUse`). `xor r9d, r9d` after a call reads the R9 just passed, so when the zero is the next call's argument the earlier call loses its R9 argument | The use check stops at `x ^ x` and `x - x` (operands functionally equal): the result is a constant, not a use of x | Calls followed by register zeroing for a call with a known prototype |
| `decomp.Function.Extensions.StaleStackArgBytes` | An x64 stack argument whose slot is written partly right before the call (`mov byte [rsp+0x30], 3`) keeps the high bytes of an earlier, wider use of the slot: `CONCAT71(in_stack_.., 3)` or `in_stack_.. & 0xffffff00`. `ActionParamDouble` splits such a PIECE only when both halves can be parameters, which an 8-byte stack slot never allows | When the low piece is written between the previous call in the block and this call and the high piece is not, the argument is the low bytes (x64 8-byte slots only: on x86-32 a PIECE of two 4-byte slots is two arguments) | Byte/bool stack arguments in reused outgoing slots |
| `decomp.Function.Extensions.StaleStackArgs` | A stack slot written once and read only by calls is an argument (`Funcdata::onlyOpUse`), so MSVC's EH state (`mov qword [rsp+0x20], -2` in the prologue) becomes a 5th argument of a later call, and the fill-in of earlier slots adds `in_R8`, `in_R9`: `Free(GMalloc, p, in_R8, in_R9, 0xfffffffffffffffe)` | On x64 a stack slot whose value reaches the call through another call's INDIRECT is not an argument (the outgoing area belongs to each callee, so compilers write arguments after the previous call). Register arguments the call writes (or sets to a constant) that the dropped slot's fill-in used to carry are kept; slots the caller never wrote are not added | Calls in functions with an EH state slot or a local in the outgoing area |
| `decomp.Function.Extensions.FoldedStackCopies` | A stack store of another variable's value is a direct write only while its COPY exists (`ActionDirectWrite`, isStackStore). A struct `GetEnumerator(&a)` fills in and the code copies to `b`, whose address later calls take, loses the store once RulePropagateCopy folds it into the loop MULTIEQUAL: the INDIRECTs at the calls taking `&b` lose their address force, and when every path ends in a noreturn call the copy is dead: `MoveNext(&b)` reads the zeroed `b` | A stack MULTIEQUAL with an input moved (COPY, PIECE, SUBPIECE) from a marker-defined value at another stack address is a direct write | Out-parameter structs copied in functions ending in throw helpers (IL2CPP) |
| `decomp.Function.Extensions.FloatGrouping` | `FLOAT_ADD`/`FLOAT_MULT` print with the associative integer tokens (`PrintC::opFloatMult` uses `multiply`), so `a * (b * c)` prints as `a * b * c`, which C evaluates as `(a * b) * c`: a different float rounding | A float + or * whose right operand is the same operation keeps its parentheses | Float expressions computed right to left |
| `decomp.Function.NaNIgnore` (Ghidra's `nanignore` option) | Default `compare`: NaN tests protecting a float comparison are dropped (RuleIgnoreNan), so `comiss`/`ja` code assumes no NaN | `pcode.NaNIgnoreNone` keeps them (`!NAN(x) && 0.0 <= x`), `pcode.NaNIgnoreAll` drops every NaN test. This is a port of Ghidra's own option, not part of the `Enhanced` preset: it adds a NaN test to most float comparisons | Exact NaN behaviour, together with `NaNExactCompares` |
| `decomp.Function.CalleeReads` (`analysis.CalleeReads`) | The core never takes the caller's own input passed on unchanged to a call as an argument, nor a value that is also read after the call or tested before it (`AncestorRealistic`, `ancestorOpUse`); Ghidra's Java side covers this by committing the callee's prototype first (Decompiler Parameter ID) | `pkg/analysis` scans the callee's entry path (64 instructions, one path, stopping at a call) for registers it reads before writing; such an argument candidate Ghidra left inactive is kept. A register stored to the home area (`[rsp+8..0x20]`, also through a copy of RSP) counts as read when it is an XMM register, or an integer register while R9 is not homed (a varargs callee homes the variadic slots up to R9, so it gains no arguments). The kept candidate yields to a candidate Ghidra accepted in the same slot unless the callee reads only the kept one (a thunk using XMM0 as scratch while passing RCX on) | Wrappers that forward their parameters, calls whose argument registers are read again after the call, IL2CPP null-checked receivers |
| `decomp.Function.CalleeReads`, not-inputs side (`analysis.CalleeReads.CalleeNotInputs`) | A register merely live at a call (RCX left holding a class pointer from a class-init check, XMM0 from the last float operation) is taken as an argument | Every path of the callee is followed; a parameter register written before read, or untouched on a path that returns, on every path is not an input, and the other register of a homed slot (`mov [rsp+8], rcx` makes slot 1 an integer slot, so XMM0 is not an input). Stack slots past the last one any path reads are not inputs (needs the full-path scan of the prototype side; not for a function homing R9 whole). Such a candidate Ghidra accepted is dropped. A path ending at a call, an indirect jump or the limit gives no answer | `call f(xmm0)` after `mov rcx, [class]` |
| `decomp.Function.CalleeReads`, prototype side (`analysis.CalleeReads.CalleeInputs`) | A callee without a prototype taking stack parameters gets them from the caller's stack trials: a slot written partly (`mov byte [rsp+0x30], 3` into an 8-byte slot) prints as `CONCAT71(in_stack_.., 3)`, and a thunk that rearranges its stack parameters and jumps (`jmp f`, a tail call) loses them and its register parameters | For a callee with stack parameters, every path is followed with the stack pointer tracked from the entry (a register computed from RSP follows it; one stepped from itself, as a loop walking a buffer does, does not): parameter registers and stack slots (entry RSP + 0x28 + 8k) read before written give the full input list with sizes, a stack slot loaded into an XMM register typed float. A register untouched at an inner call is an input only when that callee reads it first. The callee's inputs are locked to that list. No answer for an indirect jump, a call to an unknown target meeting an untouched register, a slot used as both integer and float, R9 homed whole (maybe varargs), a register-only function taking a parameter register copied whole as 8 bytes (its type is unknown: locking it would add casts), or a host prototype that has parameters. A function whose parameters are all floats is locked too (its sizes come from scalar operations), which fixes a double argument split to 4 bytes (`floor(SUB84(d, 0))`). An indirect tail jump (`jmp [vtable+n]` with RSP at its entry value, virtual-call invokers) ends a path when every register slot is decided | Stack-parameter calls in code without symbols (IL2CPP constructors, stack thunks) |
| `decomp.Function.CalleeReads`, return side (`analysis.CalleeReads.CalleeFloatReturn`) | A function without a prototype has an unknown return, so a float a callee returns is printed through a cast (`(float)FUN_x()`) or dropped, and a function returning a float can print as `void` | Every return path is followed: XMM registers carry the size of their last low-lane write (scalar op or load; a whole-register copy passes it on; `xorps x, x` is 0.0 of either size; a direct call passes on the callee's own answer, 3 deep). A path counts when that write is not read again before the return and RAX is not written after it; a path writing RAX after XMM0 vetoes (one that never writes XMM0 returns the caller's value and says nothing). The callee's return, and the function's own return, are locked to `float`/`double` when the host does not lock them; a callee locked this way keeps its XMM0 argument (Ghidra's `guardCalls` skips the call's output range) | Float getters, math helpers, `float f(float)` |
| `decomp.Function.InstructionHooks` (`bridge.InstructionHook`) | No equivalent | Callers change instructions before flow is followed. Extensions in `pkg/ext` plug in here | Extension point |
| `pkg/ext/branchassume` | `Funcdata::overrideFlow` rejects overrides of conditional branches | Fixes chosen conditional branches to one side, as a user would patch `jz` to `jmp` or to no-ops. The dropped side is not decompiled, each fixed branch is marked in the output, and `Hook.Unapplied` lists addresses no flow reached | Junk-byte obfuscation, with directions from a runtime trace |
