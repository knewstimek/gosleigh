# B6: x86 context initialization + golden fixtures

## Objective

Implement pspec context default parsing and apply it to the x86 backend so that
NOP (0x90), RET (0xC3), PUSH EBP (0x55) produce non-zero p-code op sequences.
Generate x86 golden fixture JSON files for those opcodes.

## Why

x86.sla loads successfully (4 spaces, 1630 UserOps, 43 ContextFields) but every
opcode returns 0 ops with no error. Root cause: context bits `addrsize` and `opsize`
default to 0 (16-bit mode) instead of 1 (32-bit mode) as required by x86.pspec.
With wrong context, Sleigh constructor pattern matching selects 16-bit variants
(or no match) for every opcode, returning an empty op list silently.

x86.pspec specifies:
  <context_set space="ram">
    <set name="addrsize" val="1"/>
    <set name="opsize" val="1"/>
  </context_set>

The existing code registers context variable bit ranges from xrefs.ContextFields
(in integration_test.go and golden_test.go) but never calls SetVariableDefault to
apply the pspec-supplied initial values. Applying addrsize=1 and opsize=1 is the
only missing step.

## In-scope

1. `pkg/sla/pspec.go` -- new file:
   - `type PspecContextEntry struct { Name string; Value uint64 }`
   - `type PspecData struct { ContextSet []PspecContextEntry }`
   - `func ParsePspec(path string) (PspecData, error)` -- parses XML,
     returns only `<context_set><set name="..." val="..."/>` entries.
     Does NOT include `<tracked_set>` entries (tracked values are not
     context register defaults in Ghidra).

2. `pkg/sla/pspec_test.go` -- new file:
   - Unit test for ParsePspec against `../../testdata/sla/x86.pspec`
     (runtime.Caller-relative path, same pattern as goldenFixturePath).
   - Assert: ContextSet contains addrsize=1 and opsize=1. No tracked_set entries.

3. `pkg/sla/x86_golden_test.go` -- new file (package `sla_test`):
   - `goldenEngineX86(program []byte) (*sla.Engine, address.Address, error)`:
     a. Reads `testdata/x86-packed.sla` (exists at pkg/sla/testdata/x86-packed.sla).
        Use the same container Read() + DecodeBoundariesPayload() pattern as
        integration_test.go loadTestPayload().
     b. Calls boundaries.BuildXrefs().
     c. Creates backend := sla.NewBackend().
     d. Registers each context variable: backend.RegisterContextVariable(cf.Name,
        int(cf.StartBit), int(cf.EndBit)) for each cf in xrefs.ContextFields.
     e. Parses x86.pspec: sla.ParsePspec(x86PspecPath()) where x86PspecPath()
        returns the path to ../../testdata/sla/x86.pspec using runtime.Caller.
     f. Applies context defaults: for each entry in pspecData.ContextSet,
        backend.SetVariableDefault(entry.Name, entry.Value).
     g. Sets instruction bytes at ram base address 0x0 (16 bytes, zero-padded).
     h. Builds and returns sla.NewEngineFromBoundaries(boundaries, sla.EngineConfig{...}).
   - TestGoldenX86 test function with subtests:
       {"NOP",      []byte{0x90}},
       {"RET",      []byte{0xC3}},
       {"PUSH_EBP", []byte{0x55}},
     Same update/compare logic as TestGolden6502: GOSLEIGH_UPDATE_GOLDEN=1 writes
     fixture, otherwise compares against stored fixture.
   - Each subtest MUST assert len(ops) > 0 (log and fail if 0 ops returned after
     context init, even in update mode -- 0 ops is a hard failure not a fixture gap).

4. `testdata/golden/` -- new fixture files:
   x86_NOP.json, x86_RET.json, x86_PUSH_EBP.json generated by running the test
   with GOSLEIGH_UPDATE_GOLDEN=1. Use the same GoldenOp JSON schema as BRK.json.

## Out-of-scope

- No changes to backend.go, xrefs.go, engine.go, or any other existing production files.
- No 64-bit x86 (x86-64.sla), ARM, or other architectures.
- No CLI, ELF loader, or Phase C work.
- Do not add MOV/ADD/SUB or other complex opcodes -- just the three listed above.
- Do not modify integration_test.go or golden_test.go (6502 tests must be untouched).

## Invariants

- Existing 6502 golden tests (BRK.json, NOP_EA.json, LDA_imm.json) must pass unchanged.
- `go build ./...` must pass.
- `go test ./pkg/sla/...` must pass with all tests green.
- x86 NOP/RET/PUSH_EBP subtests must assert ops > 0 and pass (not skip, not "unimplemented").
- ASCII-only in all code and test output. Tabs for indentation.
- Comments in English. Include C++ cross-reference where relevant (e.g., SleighLanguage
  java setContextForProcessor applies pspec context_set -- Go pspec.go mirrors that logic).

## Constraints

- `testdata/x86-packed.sla` lives at `pkg/sla/testdata/x86-packed.sla` (already exists).
- `x86.pspec` lives at `testdata/sla/x86.pspec` (project root, two levels up from pkg/sla/).
- `testdata/golden/` lives at project root `testdata/golden/` (same as existing fixtures).
- Both paths must be derived via runtime.Caller to be correct regardless of working directory.
- `ParsePspec` uses standard library `encoding/xml` only. No third-party deps.
- The `val` attribute in pspec is a decimal integer string (e.g., "1"). Parse with strconv.ParseUint.
- Do NOT call tracked_set entries via SetVariableDefault. Only context_set entries.
- pspec_test.go lives in `package sla` (internal test) so it can call ParsePspec directly.
- x86_golden_test.go lives in `package sla_test` (external test) matching golden_test.go.

## Done when

- `go build ./...` passes.
- `go test ./pkg/sla/... -run TestPspec` passes and asserts addrsize=1, opsize=1.
- `go test ./pkg/sla/... -run TestGoldenX86` passes with all 3 subtests green.
- `testdata/golden/x86_NOP.json`, `x86_RET.json`, `x86_PUSH_EBP.json` exist and
  contain at least 1 op entry each (not empty arrays, not UNIMPLEMENTED).
- `go test ./pkg/sla/... -run TestGolden6502` still passes (6502 parity unchanged).
