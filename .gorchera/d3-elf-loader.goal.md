# D3: ELF binary loader + real binary E2E decompilation

## Objective

Implement a minimal ELF binary loader that extracts the .text section from a
real x86 ELF binary and feeds it into the Gosleigh decompilation pipeline.
Verify that a function from a real binary can be decompiled to C output via
Heritage + PrintC. This is the first true end-to-end test on a real binary file.

## Why

Phases D1 and D2 verified the pipeline on hand-crafted byte sequences. A real
ELF binary test is the next proof that Gosleigh works outside a controlled test
environment. The ELF loader is also a prerequisite for any downstream tool
integration (MCP, CLI on real files).

pkg/loader/loader.go already handles BinaryPath (file-based input). What is
missing is ELF-aware section extraction: given a .text section VA + file offset,
extract the right bytes and set BaseAddr correctly so the disassembler produces
correct instruction addresses.

## Implementation

### 1. Create testdata/elfs/simple_add.elf

Create a minimal x86 (32-bit) ELF binary in testdata/elfs/ that contains a
simple "add" function. The binary must be created by the test itself using a
pre-encoded byte slice (no external assembler dependency).

The ELF binary to embed:
- Architecture: x86 32-bit (EM_386 = 3), little-endian
- A single function at VA 0x08048054 (typical Linux x86 ELF .text start):
    55              PUSH EBP
    89 E5           MOV EBP, ESP
    8B 45 08        MOV EAX, [EBP+8]   (first arg)
    03 45 0C        ADD EAX, [EBP+12]  (add second arg)
    5D              POP EBP
    C3              RET
  Total: 11 bytes

The executor must generate a valid ELF32 binary embedding these bytes as the
.text section. Use encoding/binary to build the ELF header + section headers.
Alternatively, use a pre-encoded byte array (see below).

Pre-encoded minimal ELF32 with the above .text at offset 0x54, VA 0x08048054:
Create testdata/elfs/simple_add.elf as a test fixture generated by a Go test
helper (TestGenSimpleELF) that writes the binary and verifies the structure,
OR embed the raw bytes directly in the test.

The simplest approach: embed the 11 function bytes directly and call EngineBuilder
with Bytes: (no ELF needed for this step -- see note below).

### 2. ELF loader in pkg/loader/elf.go

Create pkg/loader/elf.go with:

```go
// ELFLoader extracts x86 .text section bytes from an ELF32 binary.
// Mirrors Ghidra ElfProgramHeader / ElfSectionHeader extraction.
type ELFSection struct {
    Bytes    []byte
    VMA      uint64 // virtual address of section start
    Offset   uint64 // file offset of section start
}

// LoadELF32TextSection opens path, parses the ELF32 header + section table,
// finds the .text section, and returns its bytes + VMA.
// Returns error if the file is not a valid ELF32 EM_386 binary.
func LoadELF32TextSection(path string) (ELFSection, error)
```

Use Go standard library debug/elf for parsing. No external dependencies.

The function must:
1. Open the file, parse it with debug/elf.Open
2. Find the section named ".text"
3. Read its bytes via Section.Data()
4. Return ELFSection{Bytes: bytes, VMA: uint64(section.Addr), Offset: uint64(section.Offset)}

Return error if:
- Not an ELF file or not ELF32 or not EM_386
- No .text section found
- Any read error

### 3. Create testdata/elfs/simple_add.elf

Create a test helper that generates the ELF binary programmatically, OR
use objcopy/objdump if available on the system. The simplest path:

Create a Go file testdata/elfs/gen_test.go that writes simple_add.elf using
Go encoding/binary. The minimal ELF32 structure is:

ELF header (52 bytes) + Program header (32 bytes) + .text bytes (11 bytes)
+ section headers + section name string table.

If this is too complex for the executor, use the alternative approach below.

### 3 (ALTERNATIVE -- PREFERRED): Skip ELF file, test ELFLoader with an existing ELF

If generating a valid ELF32 from scratch is complex, use this approach instead:
- Check if /bin/ls or any other x86 ELF is available (unlikely on Windows host)
- If not, create a minimal ELF32 byte array embedded in the test as a var (see below)

Minimal ELF32 with 11-byte .text section (pre-encoded):
This is a 168-byte array. The executor must construct it properly using
encoding/binary with ELF32 header fields. If this is too risky, use approach 4.

### 4 (FALLBACK): Skip ELF generation, test ELFLoader with a known-good simple case

If ELF generation from scratch proves complex, the fallback is:
- Create LoadELF32TextSection using debug/elf
- Write TestELFLoader that:
  a. Creates a temp file with a minimal valid ELF32 (using encoding/binary or
     a pre-computed byte slice embedded in the test)
  b. Calls LoadELF32TextSection on it
  c. Verifies that the returned bytes match the expected .text content
  d. Does NOT require the full decompilation pipeline to run on this binary
- Write TestX86ELFE2E that:
  a. Uses the returned ELFSection.Bytes + VMA with EngineBuilder.Bytes + BaseAddr
  b. Runs bridge.Build -> Heritage -> PrintC
  c. Asserts non-empty C output

### 5. TestX86ELFDecompile E2E test

Add TestX86ELFDecompile to pkg/loader/loader_test.go:
  a. Call LoadELF32TextSection on testdata/elfs/simple_add.elf (or a temp ELF)
  b. engine := loader.EngineBuilder{SLAPath, PspecPath, Bytes: section.Bytes,
       BaseAddr: section.VMA}.Build()
  c. bridge.Build(engine, bridge.BuildConfig{Name:"add", Entry:section.VMA, MaxInstructions:20})
  d. Assert len(instructions) >= 5
  e. Heritage + BatchAActions + BlockStructure + FinalStructure
  f. PrintC output non-empty
  g. t.Logf("ELF E2E C output:\n%s", output)

Note on MOV [EBP+8] (memory indirect): this opcode has not been tested yet.
If the p-code for MOV EAX, [EBP+8] produces a LOAD op but bridge/heritage
handles it incorrectly, fix the gap. The bytes 0x8B 0x45 0x08 decode to:
  LOAD RAM[EBP + 8:4] -> EAX
which should produce a LOAD p-code op.

## Key bytes for simple_add function

    55 89 E5 8B 45 08 03 45 0C 5D C3

As Go byte slice: {0x55, 0x89, 0xE5, 0x8B, 0x45, 0x08, 0x03, 0x45, 0x0C, 0x5D, 0xC3}

These are: PUSH EBP / MOV EBP,ESP / MOV EAX,[EBP+8] / ADD EAX,[EBP+12] / POP EBP / RET
